## 1. 作業の進め方（承認ルール）
- ユーザーの指示・承認なしに、ファイルを作成・修正・削除しない
- ファイルを作成・修正する前に、対象ファイルと変更内容を説明し、承認を得る
- 承認は1回の作業ごとに得る（以前の承認を別の作業に流用しない）
- gitのコマンド操作は勝手に行ってはならない。コマンドのみ教える事。
- 確認用サーバー（`localhost:8765` など）は基本的に止めておく。表示確認が必要になったときは、ユーザーに伝えて許可を得てから起動し、確認が終わったら止める

## 2. 秘密情報の取り扱い
- 個人情報・パスワード・ID・APIキー・決済情報などの秘密情報は秘密を厳守する
- 秘密情報をソースコード・設計書・ドキュメント・ログに直接書き込まない
- 秘密情報をチャットの回答や外部サービスへ送信・出力しない
- 秘密情報が必要な場合は、環境変数や設定ファイル（Git等で共有しないもの）で管理し、実際の値はユーザー自身が設定する
- 検証用サイトでは実在する人物の個人情報を使わず、ダミーデータを使う
- 秘密情報らしきものを見つけた場合は、内容を表示せずにユーザーへ報告する

## 3. 回答の正確さ
- わからないことは「わからない」と回答する
- 推測で答える場合は、推測であることを明示する
- 確認が必要な事項（料金、サービスの仕様、法律・制度、著作権など）は、確認が必要である旨を伝える

### 描き方のルール（重要）
- **「貴族が民を救う」構図にしない。** 障害のある方を「救われる民」「かわいそうな存在」として描かない
- ベル様は「人の中に眠る力を見抜き、枠を壊す存在」。障害のある方は「それぞれ違う力を持つ仲間・騎士」として描く。枠を壊すのは全員の力
- 差し出した手は「救ってあげる」ではなく「共に行こう」という誘いとして意味づける
- **物語はフィクション。** 活動記録・企業向けページには**事実だけ**を書き、物語と事実をはっきり分ける

### ページ構成（案・合意済み）
見出しは世界観の名前にし、必ず分かりやすい日本語の補足を添える。

| ページ | 世界観での名前 | 中身 |
|---|---|---|
| トップ | 謁見の間 | ベル様のイラスト、キャッチコピー、Xフォロー、物語の地図、最新の発信 |
| ベル様とは | 伝承 — プロフィール | ベル様の使命・物語。起業家との関係をどこまで出すかは未決 |
| 理念・メッセージ | 宣言 — ベル様の考え | 障害者福祉について伝えたい核心 |
| 発信まとめ | 叡智の書 — コラム | Xの投稿をテーマ別に整理（Xは流れて消えるのでHPに残す・検索対策） |
| 活動記録 | 年代記 — 活動の歩み | 登壇・企業との取り組み・メディア掲載など（事実のみ） |
| 企業の方へ | 盟約の門 — ご相談 | 受けられること、相談の流れ |
| 拠点 | 本拠地 — ワクワクリエイト | わくわくHPへのリンク（わくわくHPの公開後） |
| ギャラリー | 肖像画の間 | イラスト・アイコン・ファンアートのルール |

- 進め方：最初は**1ページの縦長サイト**（トップ・ベル様とは・理念・X・企業の方へ・問い合わせ）で公開し、発信がたまってから下層ページへ広げる

### 動き（ユーザーの好み）
- ユーザーは「動きのあるおしゃれなデザイン」が好み。特に**カーソルの光が画面の外から飛んできて収まる演出**を気に入っている
- ただし福祉に関わるサイトなので、次の点は必ず守る
  - `prefers-reduced-motion`（端末の「動きを減らす」設定）のときは、すべての動きを止める
  - 本来のカーソルは消さない（弱視の方がカーソルを拡大していることがあるため）
  - カーソル演出はパソコンのみ（`pointer: fine`）。スマホでは何もしない
  - 自動で切り替わるスライド、激しい点滅（1秒に3回を超えるもの）、スクロールを乗っ取る演出は使わない
  - 動きを止めても、情報はすべて読めるようにする

### トップページ試作（dev/）の内容
- ユーザーの評価：「結構あり」。ベル様本人にも確認を取る予定
- **画像ファイルは使っていない。** 地図や飾りは、すべてSVG・CSSで描いている（権利の心配がないため）
- 構成：ヘッダー → ヒーロー（ベル様の肖像の枠＋キャッチコピー）→ 物語の地図 → 章の一覧 → 最新の伝令（X）→ 盟約の門 → フッター
- **背景**：群青のグラデーション＋光沢（radial-gradient）＋ `img/damask.svg` のタイル＋ `body::before` の細かなノイズ（ベルベットの毛足）
- **物語の地図**（`index.html` 内のSVG。viewBox 0 0 1000 680）
  - 羊皮紙：`#burn`（feDisplacementMap で縁をゆがませる）、`#grain`（紙の繊維）、`#stains`（しみ）、`#vignette`（焼けた縁の暗さ）
  - 海岸の波線：`<mask id="coastRings">` で、島の形の太さ違いの線を白黒交互に重ねて等間隔の線を作り、`#rough` で手描き風にゆらしている
  - 島は `<path id="isle-*">` で定義（main / herald / pact / kiyosu / unknown）
  - 地図記号：`#mountain`、`#tree`、`#ship`。額縁の角の飾りは `#flourish`
  - 章の地点：`<a class="pin">`。押すと下の章の一覧（`#ch-0`〜`#ch-4`）へ移動する
  - 地図と同じ内容を「章の一覧」に文章でも載せている（アクセシビリティのため）
- **動き**（すべて `@media (prefers-reduced-motion: no-preference)` の中）
  - `.reveal` → スクロールで表示（IntersectionObserver で `.is-visible` を付ける）
  - コンパスが回転して収まる、章の印が上から順に落ちる、航路の点線が流れる、船がゆれる、霧がただよう
  - 章の印の落下アニメーションは `backwards` 指定にしている（`forwards` にすると、終了後にホバーの拡大が効かなくなるため）
- **カーソルの光**（`js/main.js`）：画面外（-80, -80）から追従して収まる。リンクの上では光の輪になる。小さな星の粒が舞う
- **フォント**：Google Fonts の Cinzel（欧文見出し）、Shippori Mincho（和文見出し）、Noto Sans JP（本文）。いずれもOFLライセンスと認識しているが、**本番前に確認が必要**
- **仮のもの**：ベル様のイラスト（枠のみ）、キャッチコピー「可能性は、まだ地図にない。」、本文すべて（「（仮）」と表示）、Xの投稿表示、相談ページへのリンク
- **見た目の確認**：前の担当（Claude）はブラウザで見た目を確認できていない（ブラウザ拡張に接続できなかった）。確認したのは、ファイルの読み込み・SVGとJavaScriptの書き方の誤りがないことだけ。見た目はユーザーがブラウザで確認済み

### 確認用サーバーの起動方法
```bash
cd dev && python3 -m http.server 8765 --bind 127.0.0.1
```
Windowsのブラウザで `http://localhost:8765/` を開く。

## 7. 権利・法律に関する注意

### 参考画像（HPイメージ画像/）
- `イメージ地図.webp`、`コンセプトカラー、柄.jpg` は**通販サイトの商品画像からダウンロードしたもの**
- 雰囲気の参考専用。**HPには絶対に使わない**

### ベル様・トーマのイラスト（ChatGPTで生成）
**作成経緯（本人に確認済み）**
- ベル様：本人の写真をChatGPTに入力し、「高貴に」「かっこよく」と指示して生成した
  - 元の写真は自撮りと思われる。カメラマンが撮ったものだった場合も、どのように使ってもよいと許可を得ている
- トーマ：「翼のあるユニコーン」と指示し、色は本人が個人的に作ってもらった**一点もののぬいぐるみ**に近づけた（市販のキャラクター商品ではない）
- 写真・ぬいぐるみの面では、大きな権利上の問題はないと考えられる（推測。法的な判断ではない）

**著作権の考え方**
- 指示が短い（「高貴に」「かっこよく」）ため、イラストそのものに著作権が認められにくい可能性がある（推測）。他人に無断で使われても止めにくいおそれがある
- 商標登録は、現段階では考えていない（ユーザーの意向）
- 文化庁「AIと著作権に関する考え方について」（2024年）の整理では、AI生成物の著作物性は、人の創作的寄与（指示の内容・生成の回数・候補からの選択など）を総合して判断される。人が加筆・修正した部分には、通常は著作物性が認められる
- 同じキャラクターを継続して生成していることは、プラスに働く**可能性はある**。ただし判例が少なく、確実ではない
- ChatGPT（OpenAI）の利用規約で、生成物の権利が利用者に帰属するとされていた**記憶があるが、未確認**。現在の規約で確認が必要
- 対策の候補：人の手で加筆・清書する、名前やロゴを商標登録する（弁理士への確認が必要）
- 最終的な判断は、弁護士・弁理士に相談するようユーザーに伝えている
